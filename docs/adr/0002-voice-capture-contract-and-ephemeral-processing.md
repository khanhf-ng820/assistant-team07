# Voice Capture Contract and Ephemeral Inline Processing

Status: accepted

CARENTA's Voice Capture pipeline exposes `POST /api/v1/capture/voice` (with a `/v1/captures/voice` alias) accepting bounded JSON base64 audio (<= 2 MB, <= 30 seconds) rather than `multipart/form-data`, validates magic bytes and strips M4A container metadata (`udta`/`meta`) in memory, sends inline audio bytes to `gemini-3.5-flash-lite` via the async `google-genai` Python SDK instead of the Gemini Files API, and returns a normalized, unsaved Capture Draft aligned with the shared `VoiceDraftLike` review contract. Using JSON base64 keeps the API free of `python-multipart`, stays symmetric with receipt OCR and OpenAPI-to-TypeScript contract checks, and avoids persisting raw voice recordings by default—raw clips are discarded immediately on the server and deleted from device temp storage after upload or cancellation, while leaving an optional injectable storage hook for future media-retention wiring (#52). Because Gemini runs asynchronously after recording stops, the mobile processing screen shows real loading feedback followed by a progressive reveal of the actual returned transcript rather than fabricated live transcription, and ambiguous or non-purchase speech resolves to an editable Capture Draft with missing fields disabled for confirmation rather than a silent expense write.
